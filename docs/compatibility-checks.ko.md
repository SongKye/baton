# Baton 호환성 검사 확장

웹에서 읽기: 사용 중인 Baton 주소의 `/compatibility-checks.html`을 연다.
이 원문을 수정하면 `npm run docs:compat`으로 웹 사본을 갱신한다.

1차에서는 검사 통과 기준, 자동 수정의 판정 기준, 채팅 실행·재접속을 보강했다.
2차에서는 세션 휴지통·복원, Chromium의 재접속·질문 UI, 수동 보고서의 코드 출처 검증을 추가했다.
CLI 버전 표는 실제 검증 결과를 검토한 뒤 기존 절차로 갱신하며, 검사 코드 변경만으로 갱신하지 않는다.

`npm test`는 임시 설치·홈에서 실행한다. 기존 MCP 설정, 스킬 관리, 이미지 기록 읽기,
OpenCode 저장소 검사도 포함한다. 실제 CLI를 사용한 기능 검증과 테스트용 CLI를 이용한 회귀 검증은
서로 다른 근거이므로 대체 가능한 것으로 표시하지 않는다.

```bash
npm test
npm run compat:smoke -- codex --strict --json /tmp/baton-codex-report.json
# 특정 설치본을 검증할 때:
npm run compat:smoke -- codex --bin codex=/path/to/bin --expect codex=0.156.0 --strict
```

## 이번 검증에서 확인한 문제

- OpenCode가 Baton에서 지정한 폴더 대신 서버를 시작한 폴더를 세션 작업 폴더로 기록했다.
  자식 프로세스의 `cwd`와 `PWD`를 맞춘 후 동일 버전의 파일 읽기·편집·명령 실행이 통과했다.
- Antigravity의 편집 허용 모드에서 명령 실행까지 요구하면 정상적인 권한 거절을 호환성 실패로
  오판할 수 있었다. 파일 편집과 명령 실행을 별도 권한 모드의 검사로 나눴다.
- 권한 "자동"의 실제 범위가 CLI마다 달랐다. Codex는 네트워크와 `.git` 쓰기가 막혀 commit·설치가 실패했고,
  Antigravity의 편집 허용 모드는 셸 명령을 하나도 실행하지 못한 채 턴이 끝났다. OpenCode의 "전체 허용"은
  "자동"과 같은 인자였다. 세 단계의 의미를 하나로 정하고(`server/permissions.js`), auto에서 git commit과
  네트워크가 되는지를 필수 단계로, Codex 샌드박스를 모델 호출 없는 검사로 추가했다.
- 긴 실행에서 이벤트 배열을 잘라낸 뒤 번호가 되돌아가고 재접속 위치가 어긋날 수 있었다.
  단조 증가 번호와 임시 이벤트 보관을 적용하고 다중 구간 재생·연결 단절을 검사했다.
- CLI 출력의 마지막 개행 누락, 완료 이벤트 없는 정상 종료, 큰 보고서의 출력 잘림을
  정상 처리하거나 실패로 구분하도록 보강했다.
- 기존 모델 목록 테스트가 설치된 실제 CLI를 백그라운드에서 실행할 수 있었다.
  오프라인 검사는 가짜 CLI로 격리하고 실제 구독을 이용하는 검사는 별도 실행한다.

## 2차 검증과 HTTP 429 해석

- `npm test`와 Chromium 검사(`npm run test:browser`)가 통과했다.
- Chromium은 실제 렌더러·질문 UI·실행기·SSE 경로를 사용한다. 주변 탐색 화면과 CLI는 fixture이므로 전체 앱 E2E나 모바일 실기기 검증으로 보지 않는다.
- 수동 보고서는 다른 커밋, 미커밋 변경, 다른 OS·아키텍처이면 지원 버전 표에 반영하지 않는다.
- Codex 0.156.0의 첫 재검증은 명령 실행·one-shot의 HTTP 429로 10/12였다. 이후 동일 버전·동일 검사 설정으로 다시 실행한 결과 **12/12 모두 통과**했고 429는 재현되지 않았다. 당시 제한의 세부 원인은 확정하지 못했다.
- 429는 요청 빈도나 사용량 제한을 나타낼 수 있다. 현재 CLI 로그에는 `Too Many Requests`만 있어 세부 원인을 확정하지 못했다. 검사상 `quota` 분류는 한도 관련 오류를 묶은 것이며 잔액 소진을 확정한 뜻이 아니다.
- 한도 오류를 숨기거나 통과 처리하지 않고 자동 코드 수정에서도 제외한다. 한도 오류가 발생하면 반복 호출을 멈추고 제한이 해소된 후 재검증한다. 참고: [OpenAI 공식 오류 문서](https://developers.openai.com/api/docs/guides/error-codes).

추가로 복원 대상 충돌 시 원본 삭제, 도구 실패 표시 지연, Antigravity 영구 삭제 후 목록 재등장을 수정했다. 복원 중 두 번째 파일 이동 실패와 빈 임시 폴더 정리 실패도 회귀 검사에 포함한다.

## 주간 실행과 현재 모델 설정

- 이 컴퓨터의 systemd 타이머는 매주 토요일 00:00 KST에 활성화되어 있다. 꺼져 있던 동안 놓친 실행은 이후 시작 시 보충한다.
- 주간 작업은 `origin/main`의 별도 작업 트리에서 실행한다. 이번 로컬 변경이 정기 작업에 적용되려면 main에 반영되어야 한다.
- 일반 검증은 절약 정책을 적용한다. 계정별 기본 모델과 공급자의 토큰 과금 방식이 달라 절대적인 최저비용은 보장하지 않는다.

| AI 사용 구간 | 현재 기본값 | 토큰 절약 관련 설정 |
|---|---|---|
| Claude 실제 검증 | Haiku 5.5, low | 실제 필수 시나리오 13/13 통과 |
| Codex 실제 검증 | CLI 기본 모델, low | 대화와 one-shot 모두 낮은 추론 수준 |
| Antigravity 실제 검증 | CLI 기본 모델, low | 대화와 one-shot 모두 낮은 추론 수준 |
| OpenCode 실제 검증 | CLI 기본 모델 | 모델별 variant 차이가 있어 기본값 유지 |
| 호환성 문제 자동 수정 | Claude Opus 5.5, medium | 사용자 지정 정책. 모델 환경 변수로 변경 가능 |
| 오프라인·브라우저 회귀 검사 | AI 호출 없음 | 모델 토큰 사용 없음 |

주간 작업은 AI 없는 회귀 검사를 먼저 실행한다. 실패하면 실제 AI 검증을 시작하지 않는다. CLI 플래그 검사 실패 또는 인증·한도·네트워크·실행 환경 오류가 발생하면 해당 CLI의 후속 생성 요청을 중단하고 실패로 기록한다. 네트워크 오류는 주간 작업에서 한 번만 재시도하고, 인증·429 오류를 코드 자동 수정 대상으로 보내지 않는다.

필수 시나리오는 생략하지 않는다. 정상 실행에서 Claude는 대화 6회와 one-shot 1회, 나머지는 대화 5회와 one-shot 1회가 필요하며, 도구 실행에 따른 모델 내부 요청 수는 달라질 수 있다. 검증 프롬프트와 출력은 짧게 유지한다. `BATON_SMOKE_<CLAUDE|CODEX|AGY|OPENCODE>_MODEL`로 검증 모델을 지정할 수 있고, 선택한 모델·추론 수준은 보고서에 남긴다. 더 저렴한 모델을 지정할 때도 도구 호출·질문 응답 등 필수 시나리오를 통과해야 한다.

자동 수정은 Claude Opus 5.5 `medium`으로 CLI별 한 번만 시도하며, 수정 PR은 사람의 검토를 위해 열린 상태로 남긴다. 검증 도중 비싼 모델로 자동 전환하지 않는다.
