웹에서 읽기: 사용 중인 Baton 주소의 /compatibility-checks.html을 연다. 이 원문을 수정하면 npm run docs:compat으로 웹 사본을 갱신한다.

1차에서는 검사 통과 기준, 자동 수정의 판정 기준, 채팅 실행·재접속을 보강했다. 2차에서는 세션 휴지통·복원, Chromium의 재접속·질문 UI, 수동 보고서의 코드 출처 검증을 추가했다. CLI 버전 표는 실제 검증 결과를 검토한 뒤 기존 절차로 갱신하며, 검사 코드 변경만으로 갱신하지 않는다.

현재 plan 검사는 파일을 수정하지 말라는 요청을 준다. CLI의 쓰기 차단 자체를 증명하는 부정 테스트는 아니다. 모델 목록 검사도 목록의 모든 모델이 실행된다는 의미는 아니다. 오래된 스트림의 임시 보관은 실행 중인 서버의 재접속을 위한 것이며 서버 재시작 후 실행 복구는 포함하지 않는다.

이번 검증에서 확인한 문제

  • OpenCode가 Baton에서 지정한 폴더 대신 서버를 시작한 폴더를 세션 작업 폴더로 기록했다. 자식 프로세스의 cwd와 PWD를 맞춘 후 동일 버전의 파일 읽기·편집·명령 실행이 통과했다.
  • Antigravity의 편집 허용 모드에서 명령 실행까지 요구하면 정상적인 권한 거절을 호환성 실패로 오판할 수 있었다. 파일 편집과 명령 실행을 별도 권한 모드의 검사로 나눴다.
  • 긴 실행에서 이벤트 배열을 잘라낸 뒤 번호가 되돌아가고 재접속 위치가 어긋날 수 있었다. 단조 증가 번호와 임시 이벤트 보관을 적용하고 다중 구간 재생·연결 단절을 검사했다.
  • CLI 출력의 마지막 개행 누락, 완료 이벤트 없는 정상 종료, 큰 보고서의 출력 잘림을 정상 처리하거나 실패로 구분하도록 보강했다.
  • 기존 모델 목록 테스트가 설치된 실제 CLI를 백그라운드에서 실행할 수 있었다. 오프라인 검사는 가짜 CLI로 격리하고 실제 구독을 이용하는 검사는 별도 실행한다.

2차 검증과 HTTP 429 해석

  • npm test와 Chromium 검사(npm run test:browser)가 통과했다.
  • Chromium은 실제 렌더러·질문 UI·실행기·SSE 경로를 사용한다. 주변 탐색 화면과 CLI는 fixture이므로 전체 앱 E2E나 모바일 실기기 검증으로 보지 않는다.
  • 수동 보고서는 다른 커밋, 미커밋 변경, 다른 OS·아키텍처이면 지원 버전 표에 반영하지 않는다.
  • Codex 0.156.0의 첫 재검증은 명령 실행·one-shot의 HTTP 429로 10/12였다. 이후 동일 버전·동일 검사 설정으로 다시 실행한 결과 12/12 모두 통과했고 429는 재현되지 않았다. 당시 제한의 세부 원인은 확정하지 못했다.
  • 429는 요청 빈도나 사용량 제한을 나타낼 수 있다. 현재 CLI 로그에는 Too Many Requests만 있어 세부 원인을 확정하지 못했다. 검사상 quota 분류는 한도 관련 오류를 묶은 것이며 잔액 소진을 확정한 뜻이 아니다.
  • 한도 오류를 숨기거나 통과 처리하지 않고 자동 코드 수정에서도 제외한다. 한도 오류가 발생하면 반복 호출을 멈추고 제한이 해소된 후 재검증한다. 참고: OpenAI 공식 오류 문서.

추가로 복원 대상 충돌 시 원본 삭제, 도구 실패 표시 지연, Antigravity 영구 삭제 후 목록 재등장을 수정했다. 복원 중 두 번째 파일 이동 실패와 빈 임시 폴더 정리 실패도 회귀 검사에 포함한다.

주간 실행과 현재 모델 설정

  • 이 컴퓨터의 systemd 타이머는 매주 토요일 00:00 KST에 활성화되어 있다. 꺼져 있던 동안 놓친 실행은 이후 시작 시 보충한다.
  • 주간 작업은 origin/main의 별도 작업 트리에서 실행한다. 이번 로컬 변경이 정기 작업에 적용되려면 main에 반영되어야 한다.
  • 현재 설정은 최저비용 모델이나 최소 토큰 사용을 보장하는 정책이 아니다.
